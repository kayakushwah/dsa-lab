See the Pattern Before You Code

The biggest DSA upgrade is learning to translate wording into an algorithm family.

Pair + target

Sorted: two pointers. Unsorted: hash map.

if(sum < target) left++;
else right--;

Contiguous / consecutive

Ask whether a window can be maintained instead of recomputing every subarray.

Frequency

Hash map. If you only need membership/duplicates, hash set.

Middle / cycle / kth from end

Linked list → slow/fast or two-pointer gap.

Next greater / smaller

Monotonic stack. Don't use O(n²) unless constraints are tiny.

Level-by-level

Tree/graph → BFS + queue.

Shortest path, unweighted

BFS because the first time you reach a node is at minimum edge distance.

Sorted search

Binary search. Also consider “binary search on answer” when feasibility is monotonic.

Repeated overlapping subproblems

DP may be appropriate. Look for repeated states + an optimal substructure.

The “Can I Do Better?” Checklist

  1. Can a hash map/set remove a repeated search?
  2. Can sorting unlock two pointers?
  3. Can prefix sums answer repeated range queries?
  4. Can a sliding window avoid recomputing a subarray?
  5. Can a stack remember unresolved candidates?
  6. Can BFS give a shortest unweighted path?
  7. Can the search space be halved with binary search?
